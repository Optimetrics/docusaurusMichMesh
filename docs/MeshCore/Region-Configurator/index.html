Region Configurator

Pick where a repeater is and what firmware it runs, and get the region commands to paste into its console. It covers the same steps as Set Regions in the Repeater Setup guide, worked out for your area.

Scoping is on hold, so the commands only define regions. They don't set the repeater's region default or cap unscoped messages, and there's nothing a companion needs to set.

Region data from the Michigan regions RFC, bundled copy (fca92a8). Need a local region for your area? Propose one.

Where the Answers Come From​

Everything the configurator knows comes from the data/ folder of the Michigan regions RFC, and it loads the latest version when you open this page, falling back to a built-in copy if it can't.

  • Subregions come from the county assignments in RFC-001 Addendum A, the same ones as the table in Pick Your Regions and the region map.
  • Local regions come from the RFC's list. Proposed ones show up as a note, so nobody picks a clashing name. If your area uses one that isn't listed, propose it below.
  • The county is a starting point, not a border. A repeater carries the regions of the area it actually covers, which is why you can change the subregion and local region after picking a county.

Propose a Local Region​

Local regions belong to the communities that use them. If your area needs one, open a local region proposal with the region name, the area, and the repeaters and operators that will carry it. Once it's agreed and added to the RFC's data, it shows up here within minutes. The data README walks through the steps.

A town missing from the search works the same way: add it to places.json in the RFC repo.
